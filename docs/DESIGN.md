# Дизайн-язык Interviewly

## Overview

**Направление: «Спокойная рабочая библиотека».** Чёткий, организованный инструмент с мягким характером. Интерфейс помогает быстро найти тему и перейти к сосредоточенному повторению. Воздух, ясная иерархия и удобство чтения важнее декоративных эффектов. Неоновый характер проявляется в небольших цветовых акцентах, а не в постоянном свечении.

Статус: целевая спецификация для следующего этапа, сформированная после дизайн-интервью. Это не описание уже реализованной темы. Точные токены и шрифты подобраны как дизайнерское решение на основе предпочтений пользователя; их визуальная проверка предстоит при реализации. Документ не разрешает автоматически начинать UI или создавать макеты.

### Контекст продукта

- В первую очередь личная платформа; в перспективе — для людей, которые настраивают подготовку к собеседованию или теоретическому экзамену под себя.
- Текущие сценарии: группы, общие категории, поиск, создание и редактирование вопросов и ответов, последовательное повторение с раскрытием ответа.
- Начальное содержимое — frontend и смежные темы: React, CSS, HTML, Redux, JavaScript, Docker. Визуальный язык не должен ограничивать приложение только программированием.
- Компьютер и телефон одинаково важны; повторение часто происходит в метро и поезде. Приоритеты: читаемость, крупные цели касания, быстрый возврат к материалу, отсутствие отвлекающего движения.
- По коду данные сохраняются в localStorage. Это не означает готовую автономную загрузку приложения или синхронизацию между устройствами. Не показывать обещаний этих возможностей до их реализации.
- Подтверждено: рабочая строгость с мягким характером, больше воздуха, тёмная тема сначала, светлая позже, бирюзовый и лавандовый, слабое свечение, мягкая типографика, плавное движение с переворотом карточки.
- Рабочее название — Interviewly. Оно не было отдельно подтверждено после вопроса о расхождении с InterviewPrep; при будущем ребрендинге уточнить. Язык текущего интерфейса — русский.
- Точные объёмы библиотеки и длина ответов не определены. Дизайн обязан выдерживать длинные названия, многострочные ответы и примеры кода без обрезки. Форматирование Markdown и подсветка кода — отдельные будущие возможности, а не уже существующие функции.

**Характер:** собранный, спокойный, дружелюбный, немного технический. Основная оболочка помогает работать; focus-режим убирает второстепенное и помогает читать.

## Colors

Нормативные значения тёмной темы находятся в YAML выше. Все компоненты используют семантические роли, а не прямые значения цветов. Фон — нейтральный графит с небольшим холодным оттенком; поверхности непрозрачные.

### Роли и сочетания

| Роль | Применение |
| --- | --- |
| `canvas` | Фон страницы и утопленные области ввода |
| `surface` | Карточки групп, блок ответа, панели |
| `surface-raised` | Меню, диалоги, всплывающие элементы |
| `surface-hover`, `surface-pressed` | Нейтральная обратная связь на интерактивных поверхностях |
| `text` | Заголовки, вопросы, ответы, основной текст |
| `text-secondary` | Описания, подписи полей, вспомогательные действия |
| `text-muted` | Метаданные, счётчики, placeholder; не основной текст ответа |
| `border-subtle` | Разделители и необязательные контуры карточек |
| `border-control` | Видимая граница поля или outlined-кнопки |
| `primary` | Главное действие, выбранная навигация, текущая позиция повторения, ссылки |
| `secondary` | Редкий акцент focus-режима, маркер ответа, декоративная деталь |
| `*-subtle` | Приглушённая подложка соответствующего акцента или статуса |
| `success`, `warning`, `error`, `info` | Только действительный смысл статуса, вместе с текстом или иконкой |

Бирюзовый — главный акцент, лавандовый — вспомогательный. Не чередовать их произвольно между одинаковыми кнопками. Вторичная кнопка нейтральная; название `secondary` у цвета не означает обязательную лавандовую заливку вторичных действий.

На яркой бирюзовой заливке использовать `on-primary`, на лавандовой — `on-secondary`. На приглушённых цветных подложках использовать соответствующий светлый акцент или основной текст. Не ставить белый текст на яркую акцентную кнопку без проверки контраста.

**Правило малого акцента:** большую часть экрана занимают нейтральные поверхности. Один основной призыв к действию на рабочую область. Цвет не заменяет текст, форму или обозначение выбора. Не окрашивать всю карточку группы ярким цветом.

Пользовательский цвет группы — небольшой маркер или иконка на нейтральном фоне. Он не меняет цвет основного действия, ошибок и focus-ring. Произвольный цвет нельзя использовать для мелкого текста без проверки контраста; название группы остаётся читаемым независимо от него.

## Typography

Основной шрифт — **Golos Text**: спокойный, открытый рисунок, подходящий для русскоязычного интерфейса. Один шрифт для заголовков и обычного текста объединяет систему. Для кода — **JetBrains Mono**. Это выбор для будущей реализации; шрифты сейчас не установлены этим документом.

В реализации предусмотреть локальные файлы шрифтов, кириллицу и латиницу, `font-display: swap`; проверить лицензию выбранных файлов и рендеринг на целевых устройствах. Системные fallback-стеки заданы в YAML. Не зависеть от внешней загрузки шрифта при каждом открытии в поездке.

### Размеры и иерархия

Размеры в rem, таблица показывает эквивалент при базовых 16px. Масштабирование текста пользователем сохраняется.

| H2 / раздел | 24px / 1.5rem | 22px / 1.375rem | 600 | 1.3 |

## Layout

### Ритм и плотность

Основа spacing — шаг 4px, полный набор в YAML. Между иконкой и подписью — `s2`; между связанными элементами — `s3` или `s4`; padding карточек — `s6` на компьютере и `s4` на телефоне; между карточками — `s4` или `s6`; между разделами — `s8` на телефоне и `s10` на компьютере. `s12` и `s16` использовать для крупных пауз, не для каждого блока.

Воздух создаётся расстоянием между смысловыми группами. Не увеличивать каждую строку списка до большой отдельной карточки. Списки должны оставаться удобными для просмотра десятков вопросов.

### Геометрия и responsive

| Токен | Значение и поведение |
| --- | --- |
| `layout.content-max` | 1200px, максимальная ширина основного содержимого |
| `layout.focus-max` | 800px, область повторения без боковой навигации |
| `layout.sidebar` | 224px, отдельна от максимальной ширины содержимого |
| `layout.gutter-mobile` | 16px |
| `layout.gutter-tablet` | 24px |
| `layout.gutter-desktop` | 32px |
| `breakpoint.sm` | 600px |
| `breakpoint.md` | 900px |
| `breakpoint.lg` | 1200px |
| `size.touch` | Минимум 44×44px для интерактивной цели |
| `size.touch-preferred` | 48×48px для основных мобильных действий |
| `size.icon` | 20px в строках, 24px в навигации |

- До 600px: одна колонка групп; формы вертикальные; основной экран прокручивается по вертикали. Удобные нижние действия повторения с учётом safe-area.
- 600–899px: две колонки групп, если фактическая ширина каждой не меньше 260px; иначе одна. Навигация компактная.
- От 900px: доступна боковая навигация. Сетка определяется оставшейся шириной контента, а не только viewport; минимум карточки 260px, максимум три колонки.
- Поиск занимает доступную ширину; на узком экране кнопка добавления переносится на следующую строку или в явно обозначенное действие. Подпись не сжимается до нечитаемой.
- Нижняя мобильная навигация содержит только работающие разделы. Не показывать пустые «Поиск» или «Настройки» как действующие маршруты. В focus-режиме её заменяют элементы повторения.
- Фиксированные нижние элементы резервируют место в контенте и учитывают `safe-area-inset-bottom`. Экранная клавиатура не закрывает активное поле и сохранение; при необходимости фиксированная панель переходит в поток.
- Диалоги до 600px становятся полноэкранными листами, на большем экране — до 640px; короткие подтверждения — до 440px. Прокрутка содержимого не скрывает возможность закрыть диалог.
- Карточка ответа растёт по содержимому. Не фиксировать высоту так, чтобы ответ обрезался или появлялась неудобная вложенная прокрутка. Горизонтальная прокрутка допустима внутри блока кода.
- При 320px и увеличении текста до 200% сохраняются порядок чтения и доступ к действиям. Не скрывать функции только из-за размера экрана; переносить их в понятное меню.

## Elevation & Depth

Глубина создаётся сменой тона поверхности, затем границей и лишь при необходимости тенью. Фон однотонный. Основные карточки матовые; размытый фон и прозрачное стекло не являются частью нового языка.

| Токен | Значение | Применение |
| --- | --- | --- |
| `shadow.none` | `none` | Карточки, строки, обычные кнопки |
| `shadow.popover` | `0 8px 24px rgba(0,0,0,0.24)` | Меню и всплывающие панели |
| `shadow.dialog` | `0 20px 56px rgba(0,0,0,0.36)` | Диалог |
| `glow.primary` | `0 0 16px rgba(112,222,207,0.10)` | Редкий акцент главного действия при hover |
| `glow.secondary` | `0 0 18px rgba(188,173,240,0.08)` | Необязательный краткий акцент раскрытия ответа |
| `overlay.scrim` | `rgba(0,0,0,0.60)` | Затемнение под диалогом |
| `layer.base` | 0 | Контент |
| `layer.sticky` | 10 | Закреплённая навигация |
| `layer.popover` | 20 | Меню вне модального слоя |
| `layer.modal` | 30 | Диалог с scrim |
| `layer.toast` | 40 | Уведомления |
| `layer.tooltip` | 50 | Подсказки |

Значения layer задают относительный порядок; при переносе в MUI согласовать со всей шкалой z-index. Меню внутри диалога располагается выше его содержимого, а не под scrim.

Свечение не постоянно, не пульсирует и не окружает все карточки. Focus-ring — отчётливый контур, не размытый glow. Текст и иконки не светятся. Тень не является единственным способом различить поверхность.

## Shapes

Радиусы в YAML: `xs` для небольших фрагментов кода; `sm` для компактных бейджей; `md` для кнопок и полей; `lg` для карточек; `xl` для диалогов и focus-карточки. `pill` — только для небольших статусов и индикатора прогресса, не универсальная форма кнопок.

| Токен | Значение | Назначение |
| --- | --- | --- |
| `border.width` | 1px | Обычные границы |
| `border.selected` | 2px | Выделенная карточка или выбор без изменения размеров |
| `focus.width` | 2px | Контур клавиатурного фокуса |
| `focus.offset` | 3px | Отступ контура |

Граница карточки — `border-subtle`; поля и outlined-кнопки — `border-control`. Состояния не должны сдвигать соседний контент: применять outline или заранее резервировать толщину границы. Вложенные элементы имеют меньший радиус, чем внешняя панель. Не складывать несколько обводок вокруг одного смыслового блока.

## Components

### Карточки групп и списки вопросов

Карточка группы: `surface`, радиус `lg`, padding 24px/16px, тонкая граница, без постоянной тени. Содержит маркер темы, название и количество вопросов; меню действий второстепенно. Не добавлять выдуманные проценты освоения или статистику. Название допускает несколько строк; сетка выравнивает карточки без скрытия содержимого.

Список вопросов: единая спокойная поверхность либо строки с разделителями, отступ по вертикали 16px. Вопрос — главное; порядковый номер и категория — второстепенные. Меню имеет отдельную цель касания минимум 44px. Ссылка открытия и меню не вложены друг в друга. Hover меняет тон, но не двигает строку вбок.

Категории представлены заголовками с количеством вопросов и раскрываемыми списками. Кнопка раскрытия доступна с клавиатуры, состояние видно по стрелке и `aria-expanded`. Пустая категория содержит короткое объяснение и действие добавления. Использовать воздух и разделители вместо каскада вложенных карточек.

### Кнопки

- Primary: бирюзовая заливка, `on-primary`, высота минимум 44px, на телефоне желательно 48px, горизонтальный padding 16px, радиус `md`. Использовать для «Добавить вопрос», «Сохранить», «Показать ответ» по текущему контексту.
- Secondary: нейтральная поверхность или прозрачный фон с `border-control`, текст `text`; для отмены, возврата, редактирования.
- Tertiary: прозрачный фон, читаемый текст, нейтральная hover-подложка; для малоприоритетных действий. Обычная текстовая ссылка подчёркивается или иным устойчивым способом отличается от текста.
- Destructive: `error` на нейтральной или `error-subtle` поверхности, с явной подписью действия. Не помещать рядом с главным действием без разделения. Удаление группы с содержимым требует понятного подтверждения или реального отменяемого действия.
- Icon-only: цель минимум 44px, видимая иконка 20–24px, доступное имя, tooltip на устройствах с указателем. Смысл не должен зависеть только от tooltip.

### Поля, поиск и формы

Высота однострочного поля — минимум 48px. Фон `canvas`, граница `border-control`, радиус `md`, padding 12px 16px; текст 16px. Label всегда виден над полем или как устойчивая подпись, placeholder даёт пример и не заменяет label. Многострочные поля растут или допускают изменение высоты; ответ не сжимается до одной строки.

Ошибка: `error`-граница, иконка при необходимости и текст под полем, связанный с ним программно. Не сообщать ошибку только цветом. Не менять высоту формы на каждый символ: оставлять разумное место для подсказок. Валидация помогает исправить ввод; не показывать красные ошибки до взаимодействия.

Поиск имеет доступное имя, иконку и очистку при наличии текста. Отсутствие результатов объясняется отдельно от пустой библиотеки. При ошибке сохранения нельзя сообщать об успехе или терять введённый текст.

### Состояния

| Состояние | Правило |
| --- | --- |
| Default | Значения соответствующего компонента, без свечения |
| Hover | Primary → `primary-hover`; нейтральные → `surface-hover`. Применять на устройствах с hover и точным указателем |
| Focus-visible | Контур `focus` толщиной `focus.width`, offset `focus.offset`; остаётся заметным одновременно с hover или ошибкой |
| Active / pressed | Primary → `primary-active`; нейтральные → `surface-pressed`; короткая смена тона, без перемещения цели касания |
| Selected / current | `primary-subtle`, акцентный маркер и обозначение выбора; не путать с кратким pressed |
| Disabled | Фон `surface-raised`, текст `text-disabled`, граница `border-subtle`, нет glow и hover; действие действительно недоступно. Причину при необходимости объяснить рядом |
| Loading | Размер кнопки сохранён, индикатор и ясная подпись, повторная отправка блокируется; состояние сообщается assistive technology |
| Error | Текстовая причина и способ исправления; `error` дополняет смысл |
| Read-only | Текст сохраняет обычную читаемость, допускает выделение; это не disabled |

### Focus-режим

Минимальная оболочка: выход, название группы, позиция «N из M», вопрос/ответ, явная кнопка раскрытия, предыдущий и следующий вопрос. Редактирование доступно, но не конкурирует с повторением. Индикатор показывает позицию в последовательности, а не уровень знаний.

Вопрос и ответ — две стороны одной карточки с одинаковыми внешними правилами. Лавандовый используется в небольшом маркере ответа; основной текст остаётся нейтральным. На телефоне главные действия доступны внизу и не закрывают материал.

Переворот запускается отдельной кнопкой; Space/Enter работают на этой кнопке. Касание текста, выделение ответа или прокрутка не должны случайно переворачивать карточку. Невидимая сторона исключается из фокуса и дерева доступности. После открытия ответ читается в правильном порядке; сообщать короткое изменение состояния, не озвучивать весь длинный ответ автоматически.

Для длинного ответа конечная высота определяется содержимым. При реализации переворота заранее резервировать достаточную высоту и не анимировать произвольное `height: auto`. Если 3D-механика конфликтует с чтением длинного материала, использовать раскрытие с коротким fade; полноценный доступ к ответу важнее эффекта.

### Animations и transitions

| Токен | Значение | Назначение |
| --- | --- | --- |
| `motion.instant` | 0ms | Reduced motion, немедленные состояния |
| `motion.fast` | 120ms | Цвет, граница, pressed |
| `motion.base` | 180ms | Hover, небольшое появление |
| `motion.reveal` | 240ms | Раскрытие категории, появление ответа |
| `motion.dialog` | 220ms | Диалог: opacity и смещение до 8px |
| `motion.flip` | 420ms | Один переворот карточки на 180° |
| `ease.standard` | `cubic-bezier(0.2, 0, 0, 1)` | Обычные переходы |
| `ease.enter` | `cubic-bezier(0.16, 1, 0.3, 1)` | Появление |
| `ease.flip` | `cubic-bezier(0.4, 0, 0.2, 1)` | Симметричный переворот без пружины |
| `motion.distance` | 4–8px | Максимальное смещение при появлении |
| `motion.perspective` | 1200px | Сдержанная глубина переворота |

Анимировать точные свойства, не `transition: all`. Преимущественно opacity и transform; цвет и граница — локально. Не использовать bounce, параллакс, движущийся фон, бесконечное свечение и последовательный вылет всех строк. Новое содержимое не ждёт окончания декоративного эффекта; быстрые повторные действия не ставятся в очередь анимаций.

При `prefers-reduced-motion: reduce` убрать вращение, перемещение и анимированное раскрытие; состояние меняется мгновенно, допускается fade до 80ms. Функции и информация полностью сохраняются. Свечение не анимируется в цикле даже при обычной настройке движения.

### Диалоги, навигация и обратная связь

Диалог использует `surface-raised`, радиус `xl`, shadow.dialog. Заголовок, содержимое и действия чётко разделены отступами; обязательная линия между ними не нужна. Фокус удерживается внутри, Escape закрывает там, где это не теряет данные без предупреждения, после закрытия фокус возвращается к инициатору.

Выбранный пункт навигации имеет `primary-subtle`, видимый маркер и `aria-current`. Иконки — единый набор, преимущественно простые контурные формы со скруглёнными окончаниями; не смешивать разные толщины и стили. Эмодзи не являются основной навигацией или обязательным украшением заголовков.

Пустое состояние: короткий заголовок, одна полезная фраза, одно действие. Ошибка загрузки или сохранения не маскируется под пустое состояние. Skeleton повторяет геометрию контента, не мерцает ярко. Уведомления не закрывают основные действия и не являются единственным местом, где объясняется ошибка формы.

## Do's and Don'ts

### Использовать

- Семантические токены из этого документа; при реализации перенести их в единый источник темы, включая spacing, motion и радиусы.
- Бирюзовый для основных действий, лавандовый для мягкого характера; большую часть интерфейса оставлять нейтральной.
- Отступы между смысловыми блоками, читаемые названия и умеренно компактные списки.
- Удобное касание, клавиатурное управление, видимый фокус и полноценный reduced-motion.
- Контраст как критерий приёмки: минимум 4.5:1 для обычного текста, 3:1 для крупного текста и значимых границ/индикаторов. Проверить реальные сочетания и состояния при реализации; документ не является сертификатом доступности.
- Проверку на телефоне и компьютере, при 320px и 200% текста, с длинными русскими названиями и ответами, кодом, пустыми состояниями и ошибками.
- Реальные состояния продукта: локальное сохранение, отсутствие результата, недоступное действие. Тон текстов спокойный, прямой, без давления и выдуманной мотивационной статистики.

### Ограничения

- Не возвращать старое оформление автоматически: стеклянные панели, фоновые цветные пятна и сильное свечение не задают новую систему.
- Не применять градиент бирюзовый–лавандовый ко всем кнопкам и карточкам; не делать два равнозначных ярких акцента в одной рабочей области.
- Не полагаться только на цвет, hover, tooltip, жест или анимацию для доступа к функции.
- Не обрезать ответ ради одинаковой высоты карточки, не делать весь текст ответа кнопкой переворота.
- Не добавлять декоративные дашборды, streak, баллы, проценты освоения, достижения или AI-функции без отдельного продуктового решения.
- Не менять функциональность, данные и пользовательское содержимое ради визуальной композиции.
- Не обещать offline-доступ, синхронизацию, Markdown или светлую тему, пока они не реализованы и не проверены.
- Не считать предварительную светлую палитру готовой: перед её выпуском определить все состояния и проверить контраст отдельно.

**Граница текущего этапа:** создан только дизайн-документ. Макеты Figma, установка шрифтов, изменения компонентов и темы, реализация поведения и визуальная проверка относятся к следующему этапу.
